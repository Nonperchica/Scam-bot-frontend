# คู่มืออธิบาย Mini App — ช่วงที่ 1

เปิด `/mini` เพื่อดูหน้าสำหรับผู้ใช้ ตัวอย่างนี้ใช้ข้อมูลสมมติ ไม่เรียก AI, LINE หรือ Supabase และไม่ใช้รหัส Dashboard

## แบบที่เลือกและไฟล์สำคัญ

ชุดหน้าจอใช้สีชมพู–มิ้นต์ การ์ดข้อความสั้น และมาสคอต 8 ท่า ตาม mockup ที่ผู้ใช้เลือก รูปอยู่ใน `assets/` เป็น PNG โปร่งใสที่ย่อสำหรับหน้าจอ ไม่ต้องใช้เครื่องมือสร้างภาพระหว่างเปิดแอป

|---|---|
| `MiniLayout.tsx` | หัวหน้า เมนูประวัติ/เรียนรู้/บัญชี และ state `largeText` ร่วมกันทุกหน้า |

| `components/MiniPageHeading.tsx` | รับ `title` กับ `pose` เพื่อวางหัวข้อและมาสคอตแบบเดียวกัน |

## อธิบายมาสคอตอย่างไร

`MiniMascot({ pose })` รับชื่อท่า เช่น `book` → อ่าน `mascotImages.book` → คืน `<img>` ที่มี `src` และ `alt` ตรงท่า TypeScript จำกัด `MascotPose` ให้เป็นชื่อที่มีรูปจริง หาก import รูปหาย build จะไม่ผ่าน; หากโหลดรูปจากเซิร์ฟเวอร์ไม่ได้ เบราว์เซอร์ยังมีข้อความ `alt`

`MiniDetail()` อ่าน `detectionCase.status` แล้วใช้ `statusMascots` เลือกท่า: `risk_found` → `alert`, `no_risk_found` → `calm`, `uncertain` → `inspect` ภาพเป็นตัวช่วยสื่อสาร คำว่า “ยังไม่พบสัญญาณเสี่ยง” ไม่รับรองความปลอดภัย

หน้าแรกใช้ `wave` และ `think`; หน้าเรียนรู้ใช้ `book`; วิธีใช้ใช้ `guide`; บัญชีใช้ `heart` รูปทุกท่ารวมอยู่ในตัวแอป จึงไม่ต้องส่งข้อมูลผู้ใช้ไปสร้างรูป

## ปุ่มเรียนรู้เชื่อมกับเคสอย่างไร

ตัวอย่างเคสค่าไฟมี `lessonId: 'links'` ปุ่มใน `MiniDetail()` จึงสร้าง URL `/mini/lessons?topic=links&case=demo-electricity`

`MiniLessons()` ใช้ `useSearchParams()` อ่านค่า `topic` → `find()` หาหัวข้อใน `lessonTopics` → แสดงตัวอย่างและคำแนะนำของหัวข้อนั้น ส่วน `sourceCase` ใช้ค่า `case` เพื่อแสดงบริบทผลเดิมและสร้างลิงก์กลับ กดเลือกหัวข้อจะเรียก `selectTopic()` เพื่อปรับ query ใน URL

หัวข้อไม่รู้จักจะใช้บทเรียนแรก ส่วนรหัสเคสที่ไม่มีอยู่จะไม่แสดงบริบทหรือปุ่มกลับเคสอื่น ไม่มีการเรียก AI หรือรับผลใหม่จากการกดเรียนรู้

## ตัวอย่างสั้นสำหรับนำเสนอ

“เราแยกข้อมูลออกจากหน้าจอ `sampleCases` เก็บเคสตัวอย่าง ส่วน `MiniDetail()` เลือกเคสตาม URL และใช้ `statusMascots` เลือกอารมณ์ของมาสคอต เมื่อกดเรียนรู้ เราส่ง `lessonId` ไปยัง `MiniLessons()` เพื่อเปิดบทเรียนที่เกี่ยวข้อง เป็นการแสดงคำแนะนำจากผลเดิมโดยไม่ตรวจ AI ซ้ำ”

## ลำดับการทำงาน

1. `App()` อ่านเส้นทางด้วย React Router แล้วเลือกกลุ่มหน้า `/mini`
2. `MiniLayout()` แสดงหัวหน้า เมนู และป้ายข้อมูลสมมติ ส่วน `<Outlet />` เป็นพื้นที่แสดงหน้าลูก
3. `MiniHistory()` อ่าน `sampleCases` และกรองด้วย `searchText` กับ `selectedStatus`
4. กดรายการแล้ว `<Link />` เปลี่ยน URL เป็น `/mini/cases/demo-electricity` โดยไม่โหลดเอกสารเว็บใหม่ทั้งหมด
5. `MiniDetail()` อ่าน `caseId` จาก URL ด้วย `useParams()` แล้วใช้ `find()` เลือกเคสที่รหัสตรงกัน
6. ถ้าไม่พบเคส แสดงข้อความเปิดผลไม่ได้ ไม่เลือกผลของเคสอื่นมาแทน

## รับอะไร / ทำอะไร / คืนอะไร / ถ้าพัง

| ส่วน | รับอะไร | ทำอะไร | คืนอะไร | ถ้าพังหรือข้อมูลไม่ตรง |
|---|---|---|---|---|
| `MiniLayout()` | เส้นทางหน้าลูก | จัดหัวหน้า เมนู และ state `largeText` | หน้าร่วมที่มี `<Outlet />` | ปัญหา rendering ต้องแก้จาก error; ยังไม่มีการเชื่อมบริการ |
| `MiniHistory()` | `sampleCases` และค่าจากช่องค้นหา/ตัวกรอง | สร้าง `visibleCases` โดยตรวจชื่อเคส/ข้อความและสถานะ | รายการเคสที่ตรงเงื่อนไข | ไม่มีรายการ แสดงปุ่ม `clearFilters()` |
| `MiniDetail()` | `caseId` จาก URL | หาเคสและแสดงผล เหตุผล บทเรียน และคำแนะนำ | หน้ารายละเอียดเคสเดียว | ไม่มีรหัส แสดงหน้าผลเปิดไม่ได้ |
| `MiniLessons()` | `topic` และ `case` ใน query ของ URL | เลือก `selectedLesson` และ `sourceCase` พร้อมไฮไลต์ข้อความ | บทเรียนที่สัมพันธ์กับหัวข้อและลิงก์กลับผลเดิม | หัวข้อไม่รู้จักใช้หัวข้อแรก; รหัสเคสไม่ตรงไม่เลือกเคสอื่นแทน |
| `MiniHelp()` | คำถามใน `questions` | แสดงวิธีใช้และคำตอบ | หน้าช่วยเหลือ | ปุ่มเปิด LINE จริงยังไม่เชื่อม |
| `MiniSettings()` | `largeText` และ `setLargeText` จาก Outlet context | เปลี่ยนขนาดตัวอักษรในหน้าร่วม | หน้าตั้งค่าตัวอย่าง | โหลดหน้าใหม่แล้ว state กลับค่าเริ่มต้น |
| `MiniMascot()` | `pose` ที่อยู่ใน `MascotPose` | อ่านรูปและคำบรรยายใน `mascotImages` | `<img>` ของท่าที่เลือก | import รูปหายทำให้ build ไม่ผ่าน; โหลดไม่ได้ยังมี `alt` |
| `MiniPageHeading()` | `title`, `pose` | จัดหัวข้อกับรูปในรูปแบบเดียวกัน | หัวหน้าจอ | ใช้ข้อจำกัด `MascotPose` เหมือน `MiniMascot()` |
| `MiniChatButton()` | `label` หรือข้อความเริ่มต้น | สร้าง `<Link>` ไป `/mini/chat` | ปุ่มเปิดแชตตัวอย่าง | ไม่มีการเชื่อมบริการหรือส่งข้อความจริง |
| `MiniChat()` | เคสแรกในข้อมูลสมมติ | จำลองหน้าข้อความและผลตัวอย่าง | แชตตัวอย่างพร้อมลิงก์ไปผล | ยังไม่มีช่องส่งข้อมูลหรือบริการ AI |
| `formatCaseTime()` | วันเวลา ISO ที่ถูกต้องในข้อมูลตัวอย่าง | แปลงวันเวลาด้วย `Intl.DateTimeFormat` และเขตเวลา Bangkok | ข้อความวันที่ภาษาไทย | วันเวลาไม่ถูกต้องจะเกิด `RangeError`; ช่วง API จริงต้องตรวจข้อมูลก่อนใช้ |

## คำศัพท์ที่ต้องเข้าใจ

- **Component**: ฟังก์ชันที่คืน JSX เพื่อบอก React ว่าต้องแสดงอะไร เช่น `MiniHistory()`
- **JSX**: รูปแบบเขียนหน้าจอใน TypeScript เช่น `<h1>ประวัติการตรวจ</h1>`
- **State**: ค่าที่เปลี่ยนได้ระหว่างใช้งาน เช่น `searchText`; การเรียก setter ทำให้ React แสดงข้อมูลใหม่
- **Route**: ความสัมพันธ์ระหว่าง URL กับ Component
- **Outlet context**: ส่งค่าจากโครงหน้าร่วมให้หน้าลูก ในงานนี้ใช้กับตัวอักษรใหญ่
- **Type**: กำหนดรูปแบบข้อมูล; `DetectionStatus` จำกัดชื่อสถานะ และ `DetectionCase` ระบุว่าหนึ่งเคสมีข้อมูลอะไร
- **CSS**: กำหนดรูปลักษณ์; ใช้ชื่อขึ้นต้น `mini-` เพื่อจำกัดผลกระทบต่อหน้าผู้ดูแล

## ตัวอย่างเล่าให้อาจารย์ฟัง

“เมื่อผู้ใช้ค้นหาคำว่าค่าไฟ `onChange` จะเรียก `setSearchText()` จากนั้น React แสดง `MiniHistory()` ใหม่ ฟังก์ชัน `filter()` เลือกเฉพาะข้อความที่ตรงคำค้นและสถานะ เมื่อกดรายการ ระบบส่งรหัสเคสผ่าน URL ไปให้ `MiniDetail()` และเลือกข้อมูลด้วย `find()` ช่วงนี้เป็นข้อมูลจำลอง ยังไม่ใช่การอ่านประวัติจริงหรือการตรวจ AI”

## ลองทบทวน

1. ต่างกันอย่างไรระหว่าง `filter()` ในหน้าประวัติกับ `find()` ในหน้ารายละเอียด?
2. ทำไมไม่ใช้ `sampleCases[0]` แทนเมื่อ `caseId` ไม่ตรง?
3. `setSearchText()` ต่างจากการแก้ตัวแปรธรรมดาอย่างไร?
4. ทำไมหน้า `/mini` จึงอยู่นอก `DashboardAccess`? คำตอบ: ช่วงนี้มีเฉพาะข้อมูลสมมติ; ช่วงข้อมูลจริงต้องเพิ่มการยืนยันตัวตน LINE ของตัวเอง

## ขอบเขตที่ยังไม่ทำ

LIFF, API ประวัติส่วนตัว, การตรวจเจ้าของเคส, การเปิดแชตจากปุ่ม, Rich Menu, การลบประวัติจริง และการโฮสต์ จะทำในช่วงถัดไปหลังตกลงขอบเขต ไม่ควรนำข้อมูลส่วนตัวจริงมาแทน `sampleCases` หรือเปิด API ผู้ดูแลให้หน้านี้

## ผลตรวจรอบนำแบบล่าสุดมาทำจริง — 12 ตุลาคม 2026

- Build ผ่าน; มีคำเตือน bundle JavaScript รวมใหญ่กว่า 500 kB เพราะใช้ชุดแอปร่วมกับ Dashboard ยังไม่ได้แยกโหลดตามหน้า
- Lint ตรวจ frontend ผ่านด้วย `npm run lint -- --ignore-pattern 'backend/**'`; การเรียก lint ทั้งโฟลเดอร์ติดสิทธิ์อ่านโฟลเดอร์ Python `.venv` ของ backend จึงข้ามส่วนนั้นโดยไม่แก้ config
- กรองผลเสี่ยงได้หนึ่งรายการ; ค้นหาที่ไม่ตรงแสดงสถานะว่าง; ล้างตัวกรองกลับมาสามรายการ
- เคสค่าไฟเปิดหัวข้อ `links` และกลับรหัส `demo-electricity` ถูกต้อง; เลือก OTP เปลี่ยนตัวอย่างและคำที่ไฮไลต์
- มาสคอตรายละเอียดตรงทั้งสามสถานะ; หน้าเรียนรู้ วิธีใช้ และบัญชีใช้ท่า `book`, `guide`, `heart` ตามแบบ
- รหัสเคสที่ไม่มีอยู่แสดง “เปิดผลตรวจนี้ไม่ได้”; URL บทเรียนที่ไม่มีเคสไม่สร้างปุ่มกลับเคสอื่น
- ตัวอักษรใหญ่ยังมีผลเมื่อเปลี่ยนหน้า; ตรวจจอ 320 พิกเซลกับตัวอักษรใหญ่และ 390 พิกเซลกับขนาดปกติ ไม่พบเนื้อหาล้นแนวนอนในหน้าที่ตรวจ
- รูปโหลดครบและไม่พบ console error ในการกดทดสอบ

ผลข้างต้นเป็นการตรวจหน้าจอและข้อมูลจำลอง ไม่ใช่ผลทดสอบ LINE, LIFF, API จริง หรือความแม่นยำของ AI
