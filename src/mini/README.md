# คู่มืออธิบาย Mini App

เปิด `/mini` เพื่อดูหน้าสำหรับผู้ใช้ ตัวอย่างนี้ใช้ข้อมูลสมมติ ไม่เรียก AI, LINE หรือ Supabase และไม่ใช้รหัส Dashboard

รอบเชื่อมเคสจริงเพิ่ม `/mini/result?case=<รหัสสุ่ม>` อ่านรายละเอียดจาก Bot API หลังตรวจ
LINE Login เท่านั้น ดู [วิธีตั้งค่าและอธิบายโค้ด](./LIVE_CASES.md) หน้าจริงทุกหน้าใช้ดีไซน์มาสคอต
8 ท่าชุดล่าสุดเช่นเดียวกับ mockup มีเมนูประวัติ/เรียนรู้/บัญชี และไม่ใช้ `sampleCases`
เป็นข้อมูลสำรอง หน้าประวัติจริงอ่านประวัติแชตส่วนตัวของผู้ใช้จาก `detection_logs` ผ่าน `GET /api/mini/history` และลบได้จากหน้าบัญชี

## อธิบายมาสคอตอย่างไร

`MiniMascot({ pose })` รับชื่อท่า เช่น `book` → อ่าน `mascotImages.book` → คืน `<img>` ที่มี `src` และ `alt` ตรงท่า TypeScript จำกัด `MascotPose` ให้เป็นชื่อที่มีรูปจริง หาก import รูปหาย build จะไม่ผ่าน; หากโหลดรูปจากเซิร์ฟเวอร์ไม่ได้ เบราว์เซอร์ยังมีข้อความ `alt`

`MiniDetail()` อ่าน `detectionCase.status` แล้วใช้ `statusMascots` เลือกท่า: `risk_found` → `alert`, `no_risk_found` → `calm`, `uncertain` → `inspect` ภาพเป็นตัวช่วยสื่อสาร คำว่า “ยังไม่พบสัญญาณเสี่ยง” ไม่รับรองความปลอดภัย

หน้าแรกใช้ `wave` และ `think`; หน้าเรียนรู้ใช้ `book`; วิธีใช้ใช้ `guide`; บัญชีใช้ `heart` รูปทุกท่ารวมอยู่ในตัวแอป จึงไม่ต้องส่งข้อมูลผู้ใช้ไปสร้างรูป

## ปุ่มเรียนรู้เชื่อมกับเคสอย่างไร

ตัวอย่างเคสค่าไฟมี `lessonId: 'links'` ปุ่มใน `MiniDetail()` จึงสร้าง URL `/mini/lessons?topic=links&case=demo-electricity`

`MiniLessons()` ใช้ `useSearchParams()` อ่านค่า `topic` → `find()` หาหัวข้อใน `lessonTopics` → แสดงตัวอย่างและคำแนะนำของหัวข้อนั้น ส่วน `sourceCase` ใช้ค่า `case` เพื่อแสดงบริบทผลเดิมและสร้างลิงก์กลับ กดเลือกหัวข้อจะเรียก `selectTopic()` เพื่อปรับ query ใน URL

หัวข้อไม่รู้จักจะใช้บทเรียนแรก ส่วนรหัสเคสที่ไม่มีอยู่จะไม่แสดงบริบทหรือปุ่มกลับเคสอื่น ไม่มีการเรียก AI หรือรับผลใหม่จากการกดเรียนรู้

## ตัวอย่างสั้นสำหรับนำเสนอ

“เราแยกข้อมูลออกจากหน้าจอ `sampleCases` เก็บเคสตัวอย่าง ส่วน `MiniDetail()` เลือกเคสตาม URL และใช้ `statusMascots` เลือกอารมณ์ของมาสคอต เมื่อกดเรียนรู้ เราส่ง `lessonId` ไปยัง `MiniLessons()` เพื่อเปิดบทเรียนที่เกี่ยวข้อง เป็นการแสดงคำแนะนำจากผลเดิมโดยไม่ตรวจ AI ซ้ำ”

## ลำดับการทำงาน (โหมดตัวอย่าง `/mini`)

ส่วนนี้อธิบายหน้าตัวอย่างที่ใช้ `sampleCases` ส่วนลำดับของหน้าจริง `/mini/result` ที่ login LINE
และอ่านเคสจาก Supabase ดูใน [LIVE_CASES.md](./LIVE_CASES.md)

1. `App()` อ่านเส้นทางด้วย React Router แล้วเลือกกลุ่มหน้า `/mini`
2. `MiniLayout()` แสดงหัวหน้า เมนู และป้ายข้อมูลสมมติ ส่วน `<Outlet />` เป็นพื้นที่แสดงหน้าลูก
3. `MiniHistory()` อ่าน `sampleCases` และกรองด้วย `searchText` กับ `selectedStatus`
4. กดรายการแล้ว `<Link />` เปลี่ยน URL เป็น `/mini/cases/demo-electricity` โดยไม่โหลดเอกสารเว็บใหม่ทั้งหมด
5. `MiniDetail()` อ่าน `caseId` จาก URL ด้วย `useParams()` แล้วใช้ `find()` เลือกเคสที่รหัสตรงกัน
6. ถ้าไม่พบเคส แสดงข้อความเปิดผลไม่ได้ ไม่เลือกผลของเคสอื่นมาแทน

## คำศัพท์ที่ต้องเข้าใจ

- **Component**: ฟังก์ชันที่คืน JSX เพื่อบอก React ว่าต้องแสดงอะไร เช่น `MiniHistory()`
- **JSX**: รูปแบบเขียนหน้าจอใน TypeScript เช่น `<h1>ประวัติการตรวจ</h1>`
- **State**: ค่าที่เปลี่ยนได้ระหว่างใช้งาน เช่น `searchText`; การเรียก setter ทำให้ React แสดงข้อมูลใหม่
- **Route**: ความสัมพันธ์ระหว่าง URL กับ Component
- **Outlet context**: ส่งค่าจากโครงหน้าร่วมให้หน้าลูก ในงานนี้ใช้กับตัวอักษรใหญ่
- **Type**: กำหนดรูปแบบข้อมูล; `DetectionStatus` จำกัดชื่อสถานะ และ `DetectionCase` ระบุว่าหนึ่งเคสมีข้อมูลอะไร
- **CSS**: กำหนดรูปลักษณ์; ใช้ชื่อขึ้นต้น `mini-` เพื่อจำกัดผลกระทบต่อหน้าผู้ดูแล

## ตัวอย่างเล่าให้อาจารย์ฟัง

“เมื่อผู้ใช้ค้นหาคำว่าค่าไฟ `onChange` จะเรียก `setSearchText()` จากนั้น React แสดง `MiniHistory()` ใหม่ ฟังก์ชัน `filter()` เลือกเฉพาะข้อความที่ตรงคำค้นและสถานะ เมื่อกดรายการ ระบบส่งรหัสเคสผ่าน URL ไปให้ `MiniDetail()` และเลือกข้อมูลด้วย `find()` ช่วงนี้เป็นข้อมูลจำลอง ยังไม่ใช่การอ่านประวัติจริงหรือการตรวจ AI”

## ลองทบทวน

1. ต่างกันอย่างไรระหว่าง `filter()` ในหน้าประวัติกับ `find()` ในหน้ารายละเอียด?
2. ทำไมไม่ใช้ `sampleCases[0]` แทนเมื่อ `caseId` ไม่ตรง?
3. `setSearchText()` ต่างจากการแก้ตัวแปรธรรมดาอย่างไร?
4. ทำไมหน้า `/mini` จึงอยู่นอก `DashboardAccess`? คำตอบ: Mini App เป็นของผู้ใช้ LINE ทั่วไป ไม่ใช้รหัสผู้ดูแล หน้าตัวอย่างมีแค่ข้อมูลสมมติ ส่วนหน้าจริง `/mini/result` ยืนยันตัวตนด้วย LINE Login ของตัวเอง และ backend ตรวจ ID token กับ LINE ทุกครั้ง
